# 关键逻辑说明

本文对照1.1.0服务与前端状态代码，解释输入怎样变成规则判断、持久草稿、正式答卷和统计。

## 一 共用数据与程序边界

共同示例使用四题：q_role身份单选student/worker；q_tools工具多选mongo/python/java，恰好2项；q_age数字0～120整数；q_feedback可选文本，非空2～100码点。worker跳q_age；工具同时含mongo/python跳q_feedback；年龄60～120结束；建议默认END。完整定义和结构见[数据库设计](数据库设计.md)，接口调用见[API说明](API说明.md)。

题目ID稳定，顺序是定义数组的位置。程序注册题型处理器和有限运算符，规则参数保存在问卷文档，不按具体survey_id写分支，不执行eval。新增业务能力可能需要新处理器、schema或界面，不声称所有扩展零改代码。

| 层 | 输入 | 权威职责 | 输出 |
| --- | --- | --- | --- |
| 页面 | 用户输入 | 展示、即时提示、待保存状态 | 原始答案、请求快照 |
| 请求模型 | JSON | 结构、额外字段、规模和数值边界 | 可处理模型或422 |
| 服务 | 用户、资源、revision | 权限、状态、版本、去重及事务编排 | 过程/回执/业务错误 |
| 领域 | 定义、答案 | 配置检查、条件、题型与真实路径 | 规范值、path和逐题错误 |
| MongoDB | 文档与更新 | 基本schema、索引、单文档原子性、事务 | 持久事实或存储错误 |

## 二 创建 保存与发布

### 2.1 创建者草稿

创建surveys时draft只有标题、空说明、默认策略和空题目；revision=1，current_version=0，尚无可填写版本。保存请求携带整个draft和revision，服务按_id、owner_id、revision条件更新，成功替换draft、管理时间并revision+1。旧revision返回409，不能无条件覆盖。

草稿允许题目尚未完成业务配置；它仍须满足请求结构和安全数值限制。删除或重排题目后，已有引用可能失效，发布检查指出问题，不自动猜测修复规则。

### 2.2 发布事务

```text
检查本人问卷与revision
  ↓ 截止需含时区、晚于当前时间或null
完整check_definition
  ↓
生成version=current_version+1及完整definition
  ↓
插入survey_versions
  ↓
更新surveys当前指针、published、deadline、revision和activity_seq
  ↓ 同事务提交
```

例如保存后revision=2，发布携带2；成功得到v1和新管理revision。若定义有回跳或必答范围无解，发布前拒绝，不插入版本。插入版本和移动指针必须共同成功，避免版本存在但入口仍指向旧状态。

发布响应有survey元数据，前端只合并这些字段，不用返回对象替换当前草稿。截止是问卷级当前状态，不放进历史快照；旧过程也服从当前截止和关闭。

## 三 条件解释与规则匹配

### 3.1 运算符与类型

| 题型 | 运算符 | 解释 |
| --- | --- | --- |
| 单选 | eq、ne | 与已存在选项ID比较 |
| 多选 | contains_any | 与配置选项有任一交集 |
| 多选 | contains_all | 配置选项均包含于答案 |
| 多选 | set_equals | 两集合相等，不依赖数组顺序 |
| 数字 | eq、ne、gt、gte、lt、lte | 合法数值比较 |
| 数字 | between | 闭区间，两个边界都包含 |

all要求所有子条件满足，any要求至少一个满足。不能用未来题、未到达题或空值满足条件；即使ne，也不把“没有回答”误判为“不等于某值”。发布检查条件叶子字段、操作符、值类型、有效选项、引用位置及嵌套规模。

### 3.2 顺序与默认

```text
按rules原顺序逐条判断
  ├─ 第一条true：采用该target，不继续叠加
  └─ 均false：采用default_target
         ├─ null：数组中的下一题
         ├─ 后续ID：跳至该题
         └─ END：结束
```

多条规则命中不是随机选，也不是全部执行；更具体的规则应按希望优先级排列。只向后跳或结束，杜绝循环。规则可以引用当前或前面已到达的题，不能凭题号推断已经有值。

### 3.3 三类具体推演

| 输入 | 判断 | 路径 |
| --- | --- | --- |
| role=worker、age=40、建议空 | worker命中，跳工具；年龄不在60～120 | role→age→feedback |
| role=student、tools=[mongo,java]、age=20 | 身份默认；多选不全含mongo/python；数字不结束 | role→tools→age→feedback |
| role=student、tools=[mongo,python] | 多选contains_all成立 | role→tools→feedback，年龄跳过 |
| role=worker、age=60 | worker跳年龄；between下边界命中 | role→age→END |
| role=worker、age=120 | between上边界命中 | role→age→END |

组合示例放在建议题：all(role=student, any(age>=18, tools contains_all mongo/python))。如果年龄被跳过但工具条件成立，any仍可成立；不能在身份题配置这段条件，因为会引用未来题。

## 四 路径计算与答案清理

### 4.1 正式提交的后端权威计算

1. 检查输入键不含未知题目。
2. 从第一题进入，建立clean、path和issues。
3. 将到达题加入path，用题型校验当前答案，空可选值规范成null。
4. 用已经到达的规范值判断规则，得到后续位置或END。
5. 有错误时最终抛逐题错误，不保存正式答卷；无错误才保存clean和path。

后端不信任前端path。输入中附带合法但本次跳过的q_tools，会被排除；未知题ID则直接拒绝。必答只作用于实际路径，跳过工具题不应被其必答阻塞。

### 4.2 草稿路径与正式路径的区别

草稿progress先解析raw值，并验证当前题；遇到第一道无效或未完成必答题就停止推导，避免无效值决定分支或默认路径。正式evaluate为了收集逐题问题可以继续判断后续位置，但只要存在issues就不生成答卷；不能将这两种行为写成完全相同。

原始q_age="-"可保存，解析失败不参与age条件。用户修正为40后才能继续。可选空题合法，不是“未完成必答”；它在路径中可为null，条件不满足。

### 4.3 修改前题后的清理

有效跳转从q_role直接到q_age，q_tools确定失效，应清除。若当前前题暂时无效，只是还不能决定后续路径，应先保留暂存输入，不把所有尚未到达题都删除。前端pruneSkipped与后端save分别处理确定跳过区间，最终提交仍独立evaluate。

## 五 分层校验与边界

| 层次 | 允许与拒绝 | 失败后果 |
| --- | --- | --- |
| 请求 | 限定字段、长度、数组、有限数值和绝对值≤10¹⁵ | 422，业务写入前拒绝 |
| 配置发布 | 类型、引用、规则、上下界、必答可满足性 | 不新增版本 |
| 填写草稿 | 允许缺必答、数量不足、超题目范围、中间字符串 | 结构仍受限；revision和状态仍检查 |
| 正式答案 | 逐有效路径必答、选项、数量、长度、范围、整数 | 逐题错误，不写正式答卷 |
| 数据库 | BSON形状、索引与基础约束 | 拒绝不合结构或重复键，不替代完整业务规则 |

### 5.1 选择题

单选值必须是已存在选项ID。多选必须为不重复合法ID数组；至少、最多、恰好数量由min_choices/max_choices表达。空可选数组规范成null，非空可选值仍受数量限制，不可利用“可选”绕过规则。

### 5.2 文本

统一按Python strip对应空白集合去首尾空白，再按Unicode码点计数。😀是一个码点，组合字形可能多个码点；不能写成一个视觉字符一定计1。输入组件不依赖原生UTF-16 maxlength，超限内容保留并提示，中文composition结束后再提交正式更新。

### 5.3 数字

正式答案需有限数值、幅度≤10¹⁵、满足范围及整数限制；布尔值不是数字。新草稿可以存字符串，normalized使用受限数值语法解析，再进入正式校验。旧接口直接提交字符串"18"仍可能被严格数字处理器拒绝，不能把新草稿转换行为套到旧接口。

### 5.4 配置可回答性

必答多选最多0项、必答文本最大0、必答整数0.1～0.9均无合法答案，发布拒绝。整数范围检查ceil(min)≤floor(max)，不是只比较min≤max。可选题可空，不能简单使用相同逻辑把所有空解配置都当必答问题。

## 六 自动保存调度与反馈

useAttempt维护当前answers/currentId、最后确认快照baseline、服务器revision、saving与paused。changed在输入停顿600ms后调度，持续输入最长5秒安排一次；网络耗时不属于调度保证。

```text
修改 → 标记未保存 → 调度flush
  ↓
已有请求：共用正在运行的Promise
  ↓ 无请求且dirty、未暂停
捕获不可变快照sent，携带服务器revision保存
  ↓
响应更新revision；如果当前快照仍等于sent，确认该内容
  ↓ 当前又有修改？继续串行发送新快照
直到最新快照确认，才显示已保存
```

例：请求发出A，等待期间输入B。A响应不能把本地换回A，也不能显示B已保存；先更新服务端revision，再保存B。请求失败保留当前内容和dirty，界面明确未完成；普通网络失败可重试，401或409暂停自动写入。

## 七 恢复 固定版本与位置

先GET本人进行中草稿；存在则选择继续或放弃，不存在再开始。begin找到已有过程时不使用页面默认匿名值覆盖；process引用开始时version_id，创建者发布v2后仍解释v1。

恢复位置是提示，不是可信游标。服务端重算有效路径，优先第一道无效/未完成题，否则采用路径内提示或合理末题。保存响应不把用户正在返回编辑的前题强行拉到后题，下次恢复再按服务端约束定位。

关闭/截止后的读取不能沿用available限制，否则“数据在库里”却无法查看。view允许返回read_only和原因，页面禁用写入并能展开全部已保存原始内容；save与submit仍要求开放。

## 八 登录过期 离开与放弃

401保留本页输入，原页只接受当前账号重新认证；成功后继续同步。未同步内容不交给另一个账号。主动退出通过pendingWork先调用保存，失败时由用户决定是否离开；路由离开也等待保存，操作中禁止离开。

beforeunload只能提示，visibilitychange只能尽力触发保存，二者不能保证强制断电前最后输入已送达。当前没有localStorage持久答案缓存，不承诺所有最后输入零丢失。

放弃先明确确认，再以revision及in_progress条件清空raw_answers、标abandoned。它不要求问卷开放，已有终态重发409。放弃后不能恢复内容，重新填写是新过程，不把旧过程改回进行中。

## 九 并发与终态保护

| 竞争场景 | 处理 | 保证边界 |
| --- | --- | --- |
| 两页同时开始 | 事务协调+已有查询+部分唯一索引 | 一账号一问卷最多一份进行中 |
| 同revision同时保存 | 条件更新与事务重试后检查 | 后到旧版本409，不静默覆盖 |
| 保存晚于提交/放弃 | 先检查过程状态 | 不复活终态 |
| 关闭与提交/保存同时发生 | 都写同一问卷协调字段 | 依有效事务先后，不依点击时间 |
| 同一过程重复提交 | 查submitted回执与attempt唯一 | 一份答卷，同回执 |
| 不同过程同账号禁重复 | 事务内历史查重 | 不靠全局唯一账号键破坏允许重复问卷 |

多数填写写操作都会更新surveys.activity_seq，存在问卷级热点；它不是response_count，也不递增创建者revision。放弃是单过程条件更新，不描述成跨集合提交事务。

## 十 正式提交与原子性

前端停止定时器并禁止继续编辑，等待正在进行的保存和最新内容同步。新submit仅携带过程ID和revision，服务器从该草稿读取唯一答案来源。

事务先检查本人；若已submitted则返回原回执。否则检查in_progress、revision和当前问卷开放，读取原发布版本及重复策略，解析原始输入、完整evaluate，写responses，再更新attempts为submitted、response_id、raw_answers={}和revision+1。异常整体回滚。

插入responses后再更新attempts失败的窗口已有故障注入测试，结果无半份正式记录。成功响应丢失的重试必须先返回已提交回执，不能先因旧revision误报409。事务使用snapshot/majority，需要副本集；单节点验证不等于多节点容灾。

## 十一 匿名 重复与幂等的区别

匿名控制直接身份展示，重复策略控制同账号不同次过程，幂等控制同一次过程重试，三者不是同一功能。问卷范围HMAC键用于关联匿名与实名同账号，跨问卷不同；不输出给创建者，但不能宣称管理员绝对无法关联。

允许重复时可生成多份答卷，因此responses不设survey_id+respondent_key全局唯一；attempt_id唯一只防同次重复。旧token流程有效期24小时并绑定用户/版本/匿名，保留兼容但不持久化未完成内容。

## 十二 统计计算

按版本和含时区时间筛选responses；展开answers，排除null，再执行题型统计。整卷先按respondent_key组内计次数，再合计份数/人数；选项按“选项+人”去重，多选先展开选项。数字avg/min/max按有效作答次数，空数据null；内容分页20项。

一次账号重复填三次仍可能只有一人；同账号匿名实名也合并。单选人数可在不同选项间交叉，多选比例可超过100%。默认次数分母与人数切换分别对应，不能只换标签不换分子分母。

教学例两账号年龄20、40平均30；真实8用户验收年龄20～27平均23.5，分开标注。列表累计跨版本份数，详情默认当前版本；多个聚合不是同一时点快照。

## 十三 编辑器保存与截止提示

useSurveyEditor分开跟踪本地draft、已保存快照、独立deadline输入、已发布时间和操作状态。save、publish、close互斥，但保存等待期间允许编辑；响应只合并revision/status/current_version/deadline/updated_at，不替换本地draft。

关闭先确认并保存脏草稿，保存失败不关闭；保存期间又有新输入则中止关闭，保留输入。发布先捕获待发布内容和时间，保存期间变化则中止；响应期间新修改继续保留待保存/待发布标记。未修改截止时保留原秒级精度，避免分钟控件截断。

高级JSON先绑定题目ID，完整解析、类型、引用与前向检查成功后应用；失败保持原配置。RoutingEditor另用结构保护，不直接读取缺失condition。组件保护允许正常数字编辑中间状态，不把所有中间值当损坏数据。

## 十四 错误分类与用户可恢复性

结构错误details为数组，逐题错误为对象，其他错误可能null。前端不能无条件读取rule.condition或details[q]。认证401、来源/旧token越权403、资源404、状态409、输入422和存储503分别处理。

保存失败不能误报已同步；冲突不能后台覆盖；未完成输入可以留在草稿但不能写成正式答案；未知题直接拒绝，合法但本次跳过题排除。任何前端验证都不代替后端权限与答案检查。

## 十五 数据库初始化与显式升级

启动先核对已有目标集合validator、strict和error配置，一致才创建缺少集合并建索引。不自动collMod；索引建立失败也不自动删重复数据。维护窗口停写后--check预检，--apply保存旧约束、目标指纹和进度再逐集合应用，失败恢复，进程中断后--rollback。

```powershell
.\.runtime\Scripts\python.exe backend/scripts/upgrade_database.py --check
.\.runtime\Scripts\python.exe backend/scripts/upgrade_database.py --apply --journal .local/constraint-upgrade.json
.\.runtime\Scripts\python.exe backend/scripts/upgrade_database.py --rollback .local/constraint-upgrade.json
```

日志路径不能覆盖旧日志。恢复日志不是业务备份，不能恢复被删数据；预检仅识别已知旧/目标约束，未知版本停止。本轮attempts为新增集合，原五集合约束未变，旧答卷无需造假补草稿。源码归档和数据库备份不同，第二阶段仍须设计真实新格式的迁移。
